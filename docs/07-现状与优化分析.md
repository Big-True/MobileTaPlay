# MobileTaPlay — 现状与分层优化分析

> 状态：分析（不改代码）  
> 现状：纯 Android · Kotlin · Jetpack Compose · WebView 远程游戏  
> 包：`com.mobiletaplay.app`，产物 `dist/MobileTaPlay.apk`

---

## 1. 现状快照

| 层 | 现有 | 成熟度 |
|---|---|---|
| UI | Home / Detail / Settings（Compose M3）+ GameOverlayView | 可用，细节未打磨 |
| 游戏 | GameActivity + WebView（h5mota `/games/`） | 可玩，注入/输入较糙 |
| 数据 | TowerApi + OkHttp + HomeCache | 够用，无分页/缓存策略 |
| 设置 | DataStore 三键 | 很薄 |
| 输入 | GamepadMapper + 键码注入 + 虚拟键盘 | 能玩，扩展性弱 |
| 工程 | 单模块、无测试、脚本打包 | 脆弱 |
| 文档 | docs/01–06 | 需求/选型较全，实现文档缺 |

**模块清单：** `MainActivity` · `GameActivity` · `GameOverlayView` · `GamepadMapper` · `Home/Detail/Settings` · `TowerApi` · `OrientationPrefs` · `Theme`

---

## 2. 主要短板

1. **无 ViewModel / 无单测**：状态散落 Activity/Composable，HomeCache 是进程级全局，易脏。
2. **输入仍靠注入 keyCode**：延迟、兼容、录像语义都悬；手柄映射硬编码在两处（Mapper + 文案）。
3. **WebView 单实例**：进塔、返回、旋转都可能重载；无预加载、无会话保持。
4. **搜索筛选弱**：标签/分区未产品化；详情靠扫 8 页找 name（O(n)）。
5. **UI 一致性**：游戏 Overlay 与 Compose 页仍两套绘制路径；无障碍/动态字体未做。
6. **工程**：无 CI、无 lint、无 crash 上报；APK 靠脚本复制。

## 3. 分层优化建议

### L0 工程与质量（先做，成本低收益大）
| 项 | 做法 |
|---|---|
| CI | GitHub Actions：assembleDebug + lint + unit test |
| 测试 | GamepadMapper、TowerApi 解析、OrientationPrefs 单测 |
| 静态检查 | detekt / ktlint |
| 崩溃 | 调试用 logcat 规范；可选 Firebase/哨兵仅 debug |
| 版本 | versionName/versionCode 管道化 |

### L1 架构
| 项 | 做法 |
|---|---|
| 分层 | `data` / `domain` / `ui` / `game` / `input` 拆包 |
| 状态 | HomeViewModel + SavedStateHandle；去掉 HomeCache 单例 |
| 依赖 | 轻量 Hilt/Koin（可选，单模块可先手写） |
| 设置 | 完整 SettingsRepository（映射、虚拟键、方向、隐藏规则） |

### L2 数据与列表
| 项 | 做法 |
|---|---|
| 分页 | Paging3 接 list.php |
| 详情 | 需求要 by-name API；否则本地索引缓存 name→Tower |
| 图 | Coil 交叉淡入、预取 previews |
| 离线 | 磁盘缓存上次列表（TTL） |

### L3 输入与游戏运行时
| 项 | 做法 |
|---|---|
| 统一映射 | 单一 `mapping.json`，设置可改并热更新 |
| 注入 | 固定 `window.__MTP__` 协议；减少每帧 JS |
| WebView | 保持实例 + `loadUrl` 切换；返回不 destroy |
| 手柄 | 摇杆→dpad 死区、连发、震动（可选） |
| 虚拟键盘 | 可配置布局、最近使用、横屏紧凑模式 |

### L4 UI/UX
| 项 | 做法 |
|---|---|
| 动效 | 页面转场、列表 ripple、图片 crossfade |
| 大屏/平板 | 自适应列数、双栏详情 |
| 无障碍 | contentDescription、焦点顺序、字号 |
| 主题 | 动态色（可选）、纯黑 AMOLED 模式 |
| 首页 | 收藏、继续玩、历史（本地） |

### L5 产品扩展（后置）
- 收藏 / 最近游玩  
- 存档导出（WebView localStorage 桥）  
- 桌面端（若仍要多端，复用 mapping 契约）  
- 上架 Play：签名、隐私、数据安全表单  

---

## 4. 建议优先级

| 阶段 | 内容 | 理由 |
|---|---|---|
| **P0** | L0 CI+测试骨架 · L1 ViewModel · 详情 by-name/缓存 | 稳住回归，避免越改越碎 |
| **P1** | L3 映射可配置 + WebView 不重载 · L4 收藏/继续玩 | 直接提升游玩体验 |
| **P2** | L2 分页 · L4 平板/动效 · 设置增强 | 打磨 |
| **P3** | L5 扩展与上架 | 视产品目标 |

---

## 5. 一句话

**先把「工程可回归 + 状态可测 + WebView 不折腾」做实，再优化输入协议与列表体验；UI 美化和多端/上架放最后。**
